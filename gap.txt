--- CELAH 3: DNS SERVER TIDAK MERESPONS VIA SSL TUNNEL ---
Status: Belum diverifikasi apakah DNS 10.10.11.11 reachable via tunnel.

Hipotesis: Gateway GP memblokir akses DNS (dan semua traffic internal) jika
HIP report belum dikirim dengan benar. Setelah HIP berhasil, DNS seharusnya
mulai merespons.

Cara verifikasi (jalankan saat koneksi aktif):
  powershell -Command "Resolve-DnsName fasih-sm.bps.go.id -Server 10.10.11.11 -Type A"
  
Jika timeout → server DNS masih memblokir (HIP belum diterima)
Jika resolve → masalah hanya di DNS suffix routing (sudah fix dengan bps.go.id suffix)
Jika NXDOMAIN → domain tidak ada di DNS internal (unlikely)

--- CELAH 4: ESP/IPSEC vs SSL-ONLY ---
Status: Structural gap, bukan target perbaikan saat ini.

GP resmi menggunakan ESP/IPSec (UDP 4501 ke vpn-gw02.bps.go.id).
OpenConnect hanya SSL tunnel. Ini perbedaan fundamental yang mungkin
menyebabkan perilaku berbeda (performa, routing, dll), tapi DNS
seharusnya tetap bisa jalan via SSL jika HIP diterima.
